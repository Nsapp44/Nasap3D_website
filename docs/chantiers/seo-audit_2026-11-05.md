## 5. Ce qui manque / à corriger (par impact)

1. **LCP mobile** : retirer l'animation `opacity:0` du H1 (`maquettiste-nantes.astro:439`, idem maquette-industrielle) ; préconnecter `fonts.gstatic.com crossorigin` ou auto-héberger les polices (`BaseLayout.astro:68-72`) ; réduire les CSS bloquants. Lighthouse chiffre le gain des ressources bloquantes à ~1,7-1,9 s (Google Fonts 809 ms, CSS page 604 ms, `MaquetteCarousel.css` 454 ms, BaseLayout.css 304 ms). Ces corrections ramènent le LCP vers le FCP (~3,3 s) ; passer sous 2,5 s demande aussi la compression (point 2). À re-mesurer sur la vraie prod (PageSpeed Insights) après déploiement.
2. **Compression** : vérifier gzip/brotli côté Caddy en prod (non visible dans le dépôt, chantier du développeur de Nolann). Lighthouse prod locale : 313 Kio économisables (client.js 127 Ko, HTML 67 Ko, GSAP 70 Ko).
3. **`og:image:alt` faux sur TOUTES les pages** (« Objets liturgiques imprimés en 3D » codé en dur, `BaseLayout.astro:63`) + og:image dédiée pour maquettiste-nantes. Impact partage social + cohérence.
4. **Avant le carrousel** : `realisations.astro` (19 cartes `div`, sans id/lien/H2-H3) à structurer ; libellés erronés (« Maquette filtration systems », real-17 « Objets liturgiques » décrit « Maquettes de design produit ») ; alts différents entre pages.
5. **Détails** : `lastmod` /maquettiste-nantes (2026-10-26) à mettre à jour ; sitemap manuel (penser aux nouvelles URL) ; titre de l'accueil > 60 car. ; `provider @id /#business` défini seulement sur l'accueil (dupliquer un provider minimal) ; contrastes ; /realisations sans JSON-LD ; prod actuelle (master) n'a pas encore les 2 nouvelles pages dans le sitemap (normal : non déployé).

## 6. Carrousel de projets : recommandation SEO-sûre

Réponse nette : **des pages dédiées sont recommandées, pas obligatoires, mais le `#projet-x` seul est insuffisant.** Google ignore le fragment `#` (il ne s'en sert pas pour charger/indexer un contenu différent) ; un projet n'existe pour lui que s'il a une URL. Approche en amélioration progressive :
1. Chaque projet = vraie page `/realisations/<slug>` (HTML serveur, H1, texte complet, images alt/width/height, JSON-LD `CreativeWork` + `ImageObject`), listée au sitemap.
2. Dans la grille/carrousel : un vrai `<a href="/realisations/<slug>">` par carte (crawlable), tout le texte résumé dans le HTML.
3. Par-dessus, en JS : le clic est intercepté, le projet s'agrandit en place (modale/FLIP), `history.pushState` vers la même URL, croix/clic extérieur = `history.back`/retour ; sans JS, la navigation normale amène à la page. Aucun contenu en AJAX seul, aucun `display:none` comme seule présentation.
4. Variante minimale si Nolann refuse des pages : tout le texte de tous les projets dans le HTML de `/realisations`, un `id` slug par projet, `#projet-x` ouvre le projet au chargement. C'est indexable comme contenu de la page unique, mais les projets ne se positionneront pas individuellement et n'auront pas de rich result propre.
Le design « agrandi en place » reste 100 % compatible.

## 10. Ajout du 05/11 : premier affichage rapide, le lourd après

Objectif de Nolann : garder des pages qui s'affichent en ~0,5 s, avec les animations lourdes chargées en fond. Verdict : c'est exactement la technique des gros sites et elle est compatible SEO. Sources officielles (web.dev, Google Search Central, Astro, Caddy) ; les blogs sont des indices. Rien testé sur le site.

| Technique | Principe | Risque SEO | Effort |
|---|---|---|---|
| Hero statique : H1 + image poster (frame 0) dans le HTML, `fetchpriority="high"`, jamais `loading="lazy"` sur l'élément LCP | Le LCP est le H1 ou le poster, affiché sans attendre JS ni animation | aucun | faible |
| Pas de fondu depuis `opacity:0` sur le H1 / poster | Chrome ignore un élément à opacité 0 pour le LCP ; un reveal par script retarde le LCP de la durée du fondu | aucun | faible |
| Îlot d'animation en `client:idle` (ou `client:visible` avec `rootMargin`), GSAP/ScrollTrigger en `import()` dynamique après load | Le JS lourd ne bloque plus le premier affichage (le gain de l'import dynamique est une inférence, à tester) | aucun si le texte est dans le HTML | faible/moyen |
| Séquence d'images : frame 0 tout de suite, puis passes (1 frame sur 8, puis les trous) ; frame voisine si la demandée n'est pas chargée ; WebP/AVIF ; jeu portrait dédié mobile | Rien de bloquant au premier affichage ; aucune source sérieuse sur un chargement par lots selon le scroll, à construire | aucun (canvas non indexé) | moyen |
| Polices auto-hébergées, `font-display: swap`, preload d'une seule police, `size-adjust` sur la police de secours | Supprime la dépendance à Google Fonts (809 ms bloquants mesurés) | aucun | faible |
| CSS : inliner le CSS de page (`inlineStylesheets: 'always'`) | Supprime des CSS bloquants (604 + 454 + 304 ms mesurés) | aucun | faible |
| Navigation rapide : `prefetch` Astro (survol/viewport), éventuellement Speculation Rules | La page suivante est chargée avant le clic ; attention : un prérendu exécute le JS cible (Plausible, animations) | aucun | faible ; `ClientRouter` = moyen (réinitialiser GSAP entre pages) |
| Caddy : `encode zstd gzip` ; `Cache-Control: public, max-age=31536000, immutable` sur `/_astro/*` et les frames versionnées ; HTML en `no-cache` | Les 313 Kio non compressés et le cache sont réglés côté Caddy ; brotli = module ou fichiers précompressés | aucun | faible |

Indexation (Google Search Central) : Google ne scrolle ni ne clique ; ce qui se charge à l'entrée dans le viewport est vu, ce qui se charge après un scroll ou un clic ne l'est pas. Les images doivent être des `<img src>` dans le HTML rendu. Pour les images du storyboard : aucune source officielle sur `display:none` ; le choix le plus sûr est `<img>` avec alt, visible ou visually-hidden, dans le HTML initial, plus un sitemap d'images. À valider avec l'inspection d'URL de Search Console. Intérêt confirmé : des images indexées peuvent faire apparaître le site dans Google Images.
